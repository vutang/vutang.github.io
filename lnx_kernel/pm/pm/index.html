    title: Power management trong Linux kernel description: Quản lý năng lượng trong Linux kernel từ góc nhìn driver: system suspend và các pha callback, runtime PM, power domain, wakeup source, cpuidle, cpufreq và OPP, devfreq, cách debug suspend và resume. tags: - linux-kernel - power-management - suspend - runtime-pm - cpufreq

    Power management¶

    Kernel tiết kiệm năng lượng ở hai mức: đưa cả hệ thống vào trạng thái ngủ khi không dùng (system sleep), và tắt từng thiết bị hoặc giảm tần số CPU khi chúng rỗi trong lúc hệ thống vẫn chạy (runtime). Trang này trình bày từ góc nhìn của người viết driver, theo thứ tự: các trạng thái ngủ của hệ thống, trình tự suspend và các pha callback, runtime PM, power domain, nguồn đánh thức (wakeup source), quản lý năng lượng cho CPU (cpuidle, cpufreq) và cho thiết bị (devfreq), ảnh hưởng tới hệ thống real-time, rồi cách debug.

    Trạng thái ngủ của hệ thống¶

    Trạng thái Tên trong /sys/power Mô tả
    Suspend-to-idle freeze, hoặc s2idle trong mem_sleep Dừng user space và thiết bị, CPU vào trạng thái idle sâu nhất. Không cần hỗ trợ của firmware, có trên mọi nền tảng
    Standby standby, hoặc shallow trong mem_sleep Như trên, thêm tắt CPU không phải CPU khởi động. Ít nền tảng hỗ trợ
    Suspend-to-RAM mem, với deep trong mem_sleep Tắt phần lớn SoC, chỉ giữ DRAM ở chế độ self-refresh. Cần firmware hoặc code nền tảng (PSCI SYSTEM_SUSPEND trên Arm, ACPI S3 trên x86)
    Hibernation disk Ghi ảnh bộ nhớ ra thiết bị lưu trữ rồi tắt nguồn hoàn toàn 
    cat /sys/power/state        # các trạng thái hỗ trợ, ví dụ: freeze mem
cat /sys/power/mem_sleep    # ví dụ: s2idle [deep]
echo mem > /sys/power/state # vào trạng thái đang chọn trong mem_sleep

    Ghi mem vào /sys/power/state vào trạng thái đang được chọn trong /sys/power/mem_sleep, không nhất thiết là suspend-to-RAM.

    Trình tự suspend và resume¶

    Khi nhận yêu cầu suspend, kernel thực hiện:

    1. Đóng băng (freeze) các process user space và các kernel thread đánh dấu freezable.
    2. Gọi callback của thiết bị qua từng pha: prepare, suspend, suspend_late, suspend_noirq. Mỗi pha chạy cho mọi thiết bị trước khi sang pha sau, thiết bị con được xử lý trước thiết bị cha.
    3. Tắt các CPU không phải CPU khởi động, tắt ngắt, gọi code nền tảng để vào trạng thái ngủ.

    Khi có sự kiện đánh thức, resume đi ngược lại: resume_noirq, resume_early, resume, complete, rồi rã đông các process.

    Pha Ngữ cảnh Việc thường làm
    prepare, complete Process Chặn đăng ký thiết bị con mới. Ít driver cần
    suspend, resume Process, ngắt còn bật Dừng hàng đợi, chờ I/O đang chạy xong, lưu thanh ghi, tắt clock và nguồn của thiết bị
    suspend_late, resume_early Process, runtime PM đã bị khóa Việc cần làm sau khi mọi thiết bị đã qua pha suspend
    suspend_noirq, resume_noirq Ngắt thiết bị đã bị tắt Việc phải làm khi chắc chắn handler ngắt không chạy, ví dụ với interrupt controller hoặc bus controller

    Driver khai báo callback qua struct dev_pm_ops:

    static int my_suspend(struct device *dev)
{
    struct my_dev *md = dev_get_drvdata(dev);

    my_hw_stop(md);                 /* dừng DMA, chờ việc đang chạy */
    clk_disable_unprepare(md->clk);
    return regulator_disable(md->vdd);
}

static int my_resume(struct device *dev)
{
    struct my_dev *md = dev_get_drvdata(dev);
    int ret;

    ret = regulator_enable(md->vdd);
    if (ret)
        return ret;
    ret = clk_prepare_enable(md->clk);
    if (ret)
        return ret;
    my_hw_init(md);                 /* thanh ghi đã mất khi nguồn tắt, phải nạp lại */
    return 0;
}

static DEFINE_SIMPLE_DEV_PM_OPS(my_pm_ops, my_suspend, my_resume);

static struct platform_driver my_driver = {
    .driver = {
        .name = "my-dev",
        .pm = pm_sleep_ptr(&my_pm_ops),
    },
};

    DEFINE_SIMPLE_DEV_PM_OPS() gán cùng cặp hàm cho suspend, hibernation và các pha tương ứng. pm_sleep_ptr() cho phép bỏ phần PM khi build kernel không có CONFIG_PM_SLEEP mà không cần #ifdef. Code cũ dùng SIMPLE_DEV_PM_OPS() kèm __maybe_unused. Bật tắt nguồn và clock dùng các framework ở Regulator framework và Common Clock Framework. Chuyển chân sang state sleep dùng pinctrl_pm_select_sleep_state(), xem Pin control.

    Runtime PM¶

    Runtime PM tắt từng thiết bị khi nó rỗi trong lúc hệ thống vẫn chạy, rồi bật lại khi có việc. Framework quản lý bằng bộ đếm sử dụng (usage count): driver tăng bộ đếm trước khi truy cập phần cứng và giảm sau khi xong. Khi bộ đếm về 0 và các thiết bị con đều đã suspend, framework gọi callback runtime_suspend.

    /* probe() */
pm_runtime_set_autosuspend_delay(dev, 100);     /* ms */
pm_runtime_use_autosuspend(dev);
ret = devm_pm_runtime_enable(dev);

/* mỗi lần truy cập phần cứng */
ret = pm_runtime_resume_and_get(dev);           /* bật thiết bị nếu đang tắt */
if (ret < 0)
    return ret;
/* ... đọc ghi thanh ghi ... */
pm_runtime_mark_last_busy(dev);
pm_runtime_put_autosuspend(dev);                /* cho phép tắt sau thời gian trễ */

    Callback khai báo trong cùng dev_pm_ops bằng RUNTIME_PM_OPS(my_runtime_suspend, my_runtime_resume, NULL). Các điểm cần lưu ý:

    • pm_runtime_get_sync() tăng bộ đếm kể cả khi resume thất bại, nên phải gọi pm_runtime_put_noidle() ở nhánh lỗi. pm_runtime_resume_and_get() tự xử lý việc này và được khuyến nghị cho code mới.
    • Callback runtime PM chạy ở process context và được ngủ, trừ khi driver gọi pm_runtime_irq_safe().
    • Thiết bị cha (ví dụ bus controller) chỉ suspend khi mọi thiết bị con đã suspend. Thiết bị con resume thì framework resume thiết bị cha trước.
    • Driver đã có runtime PM có thể tái dùng callback runtime cho system suspend bằng pm_runtime_force_suspend() và pm_runtime_force_resume().
    • Trạng thái runtime PM xem tại /sys/devices/.../power/runtime_status, và có thể cấm runtime PM bằng cách ghi on vào power/control.

    Power domain¶

    Nhiều SoC chia chip thành các miền nguồn (power domain) có thể tắt độc lập, ví dụ miền GPU, miền video, miền ngoại vi. Một miền chỉ tắt được khi mọi thiết bị trong miền đều đã runtime suspend. Framework genpd (generic power domain) quản lý việc này: thiết bị khai báo miền bằng property power-domains trong Device Tree, và genpd tự tắt hoặc bật miền theo trạng thái runtime PM của các thiết bị trong đó. Driver thiết bị không gọi API của power domain, chỉ cần dùng runtime PM đúng cách. Trên ZynqMP, các miền được điều khiển qua firmware PMU bằng lời gọi tới firmware.

    Wakeup source¶

    Thiết bị có thể đánh thức hệ thống khỏi suspend (nút nguồn, RTC, ngắt GPIO, Wake-on-LAN) cần được đánh dấu:

    device_init_wakeup(dev, true);                 /* trong probe() */

/* trong suspend() */
if (device_may_wakeup(dev))
    enable_irq_wake(md->irq);

/* trong resume() */
if (device_may_wakeup(dev))
    disable_irq_wake(md->irq);

    Device Tree có property wakeup-source để đánh dấu thiết bị có khả năng đánh thức. Người dùng bật tắt từng thiết bị qua /sys/devices/.../power/wakeup. Danh sách nguồn đánh thức và số lần kích hoạt xem trong /sys/kernel/debug/wakeup_sources. Phần ngắt xem Interrupt và bottom half.

    Quản lý năng lượng cho CPU và thiết bị¶

    Framework Đối tượng Cách hoạt động
    cpuidle CPU khi không có task Chọn trạng thái idle (từ chờ ngắt đơn giản tới tắt core) theo độ trễ thoát và thời gian dự kiến rỗi. Governor: menu, teo, ladder
    cpufreq Tần số và điện áp CPU (DVFS) Chọn điểm hoạt động theo tải. Governor: schedutil, performance, powersave, ondemand, conservative, userspace
    devfreq GPU, bộ điều khiển DRAM, bus Như cpufreq nhưng cho thiết bị
    OPP Bảng điểm hoạt động Danh sách cặp tần số và điện áp hợp lệ, khai báo bằng operating-points-v2 trong Device Tree, dùng chung cho cpufreq và devfreq 
    cat /sys/devices/system/cpu/cpu0/cpufreq/scaling_available_governors
echo performance > /sys/devices/system/cpu/cpu0/cpufreq/scaling_governor
cat /sys/devices/system/cpu/cpu0/cpuidle/state*/name

    cpufreq dùng regulator để đổi điện áp và CCF để đổi tần số. Khi tăng tần số, điện áp phải tăng trước. Khi giảm tần số, điện áp giảm sau.

    Ảnh hưởng tới hệ thống real-time¶

    Cơ chế tiết kiệm năng lượng làm tăng độ trễ: thoát khỏi trạng thái idle sâu mất thời gian, và đổi tần số làm thời gian thực thi thay đổi. Trên hệ thống real-time thường:

    • Đặt governor performance hoặc cố định tần số.
    • Giới hạn trạng thái idle sâu, bằng tham số command line hoặc bằng giao diện PM QoS /dev/cpu_dma_latency (giữ file mở và ghi giá trị độ trễ tối đa chấp nhận được).
    • Tắt runtime PM cho thiết bị trên đường dữ liệu có yêu cầu độ trễ.

    Chi tiết xem Real-time Linux (PREEMPT_RT) và nohz_full và adaptive tick.

    Debug¶

    Công cụ Cách dùng
    /sys/power/pm_test Chạy thử suspend tới một mức rồi tự resume: freezer, devices, platform, processors, core. Giúp khoanh vùng pha bị treo
    no_console_suspend Tham số command line, giữ console hoạt động khi suspend để thấy log tới phút cuối
    /sys/power/pm_print_times Ghi 1 để in thời gian callback của từng thiết bị
    /sys/power/pm_debug_messages Ghi 1 để bật log chi tiết của PM core
    rtcwake -m mem -s 10 Suspend và hẹn RTC đánh thức sau 10 giây, tiện cho kiểm thử tự động
    /sys/kernel/debug/suspend_stats Thống kê số lần suspend thành công, thất bại và pha thất bại gần nhất
    /sys/kernel/debug/pm_genpd/ Trạng thái các power domain

    Các lỗi thường gặp:

    • Thiết bị không hoạt động sau resume: driver không nạp lại thanh ghi đã mất khi nguồn tắt.
    • Suspend thất bại với Freezing of tasks failed: một task không vào được trạng thái đóng băng, thường là kernel thread hoặc task kẹt ở trạng thái D.
    • Treo khi resume: thứ tự phụ thuộc giữa thiết bị không đúng, ví dụ thiết bị dùng I2C resume trước I2C controller. Kiểm tra quan hệ cha con hoặc khai báo device link.
    • Hệ thống tự thức dậy ngay sau khi suspend: một nguồn đánh thức đang kích hoạt, kiểm tra wakeup_sources.

    Liên quan¶

    • Regulator framework: bật tắt nguồn của thiết bị.
    • Common Clock Framework: bật tắt clock và đổi tần số.
    • Pin control: state sleep và idle của chân.
    • Real-time Linux (PREEMPT_RT): đánh đổi giữa tiết kiệm năng lượng và độ trễ.
