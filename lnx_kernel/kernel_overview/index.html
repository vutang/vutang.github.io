    Linux Kernel Overview¶

    Trang này giới thiệu Linux kernel và cách tổ chức các trang trong tab Linux Kernel. Phần đầu trình bày bức tranh chung: kernel làm gì, ranh giới giữa kernel space và user space, các thành phần chính. Tiếp theo là lộ trình đọc gồm ba lối vào theo mục tiêu của người đọc, rồi danh sách trang của từng nhóm theo đúng thứ tự trong menu bên trái. Cuối trang là danh mục subsystem của kernel kèm trang tương ứng, và bảng các chủ đề liên quan nằm ở tab khác.

    Phiên bản kernel

    Trang này tham chiếu kernel mainline dòng 6.x. Một số trang con được viết từ các phiên bản cũ hơn; khi chi tiết phụ thuộc phiên bản, trang con ghi rõ.

    Bức tranh chung¶

    Linux kernel là phần lõi của hệ điều hành, đóng vai trò lớp trung gian giữa phần cứng và các ứng dụng: quản lý CPU, bộ nhớ, thiết bị ngoại vi và cung cấp một giao diện thống nhất để ứng dụng sử dụng các tài nguyên đó.

    Một số đặc điểm chính:

    • Monolithic kernel: các thành phần chính (scheduler, quản lý bộ nhớ, file system, network, driver) chạy chung trong kernel space. Khác với microkernel, nhưng kernel vẫn mở rộng được lúc chạy bằng loadable module.
    • Mã nguồn mở, hỗ trợ nhiều kiến trúc (x86, ARM/ARM64, RISC-V...).
    • Cấu hình được thông qua Kconfig và defconfig: chỉ build những tính năng cần thiết, phù hợp từ hệ nhúng nhỏ đến server.
    • Hỗ trợ real-time: PREEMPT_RT đã vào mainline từ 6.12, không cần vá patch ngoài để có kernel real-time (bật bằng CONFIG_PREEMPT_RT).

    Các lớp của một hệ thống Linux: ứng dụng ở user space đi vào kernel qua một số interface cố định; bên trong kernel là các subsystem lõi, cơ chế lõi, driver và mã phụ thuộc kiến trúc, nằm trên phần cứng.

    User space là nơi chạy ứng dụng và thư viện (glibc...); ứng dụng không truy cập trực tiếp phần cứng. Kernel space chạy ở mức đặc quyền cao của CPU, truy cập được toàn bộ phần cứng và bộ nhớ. Hai bên trao đổi qua các interface do kernel định nghĩa: system call (open, read, write, mmap, ioctl...), device file trong /dev, các pseudo filesystem (/proc, /sys, debugfs, configfs) và netlink socket, kênh hai chiều dạng message dùng cho cấu hình mạng và uevent của udev. Các interface này được trình bày trong nhóm Kernel Space, User Space Interfaces.

    Bảng dưới liệt kê các thành phần chính bên trong kernel, thư mục tương ứng trong source và trang trình bày thành phần đó.

    Thành phần Nhiệm vụ Thư mục trong source Trang liên quan
    Process và scheduler Quản lý process và thread, phân chia thời gian CPU, hỗ trợ nhiều core kernel/, kernel/sched/ Process và thread, Scheduler, SMP và CPU hotplug
    Quản lý bộ nhớ Bộ nhớ ảo, page, cấp phát (buddy, slab allocator SLUB), mmap, DMA mapping mm/ Quản lý bộ nhớ trong driver, Virtual Memory, DMA
    Virtual File System (VFS) Giao diện file thống nhất trên nhiều file system (ext4, tmpfs, procfs, sysfs...) fs/ VFS và page cache, Pseudo Filesystem (chưa viết)
    Networking Network stack (socket, TCP/IP, netfilter, netdev) net/ Chưa có trang trong tab
    IPC SysV IPC, POSIX mqueue (ipc/); signal (kernel/signal.c); pipe (fs/pipe.c) ipc/, kernel/, fs/ Chưa có trang trong tab
    Interrupt, workqueue, kthread Quản lý ngắt, irqchip, threaded IRQ, hoãn xử lý sang ngữ cảnh process kernel/irq/, kernel/ Interrupt và bottom half
    Đồng bộ hóa spinlock, mutex, RCU, atomic kernel/locking/, kernel/rcu/ Đồng bộ hóa trong kernel
    Timer và thời gian hrtimer, clocksource, clockevent kernel/time/ Timer và delay (chưa viết)
    Security LSM, SELinux, AppArmor, seccomp, capabilities security/ Security Subsystem (chưa viết)
    cgroups, namespaces Giới hạn tài nguyên và cô lập process, nền tảng của container kernel/cgroup/, kernel/ Container Internals (Virtualization)
    Tracing và debug printk, ftrace, tracepoint, kprobe, eBPF, KGDB, kdump kernel/trace/, kernel/debug/ Tracing và debug Linux kernel
    Device driver Điều khiển phần cứng, chiếm phần lớn source drivers/ Xem mục "Danh mục subsystem"
    Mã phụ thuộc kiến trúc Boot, xử lý ngắt mức thấp, MMU arch/ Linux Kernel Boot Process

    Allocator SLAB cũ đã bị bỏ từ 6.8, kernel hiện chỉ còn SLUB; API kmalloc và kmem_cache_* không đổi.

    Lộ trình đọc¶

    Các nhóm trang được sắp theo quan hệ phụ thuộc: nhóm đứng trước cung cấp khái niệm cho nhóm đứng sau. Sau phần nền chung, tab tách thành hai nhánh theo mục tiêu đọc là viết driver và tìm hiểu cơ chế bên trong cùng real-time. Tracing & Debug đứng cuối như một bộ công cụ dùng song song với cả hai nhánh, đọc theo tình huống.

    flowchart TD
    B[Kernel Basics] --> D[Driver Model & Device Tree]
    D --> C[Interrupt, Memory & Concurrency]
    B -. "path B: interrupt and locking only" .-> C
    C --> I[Kernel Space, User Space Interfaces]
    I --> S[Subsystem Drivers]
    C --> K[Kernel Internals]
    K --> R[Real-time & CPU Isolation]
    T[Tracing & Debug: used alongside every path]

    Bảng dưới nêu ba lối vào. Cột cuối chỉ nêu các trang đã viết xong; mỗi nhóm còn các trang khác, liệt kê ở mục "Các nhóm trang".

    Lối vào Mục tiêu Các nhóm theo thứ tự Trang bắt đầu
    A. Viết driver Viết và tích hợp driver cho một thiết bị Kernel Basics, Driver Model & Device Tree, Interrupt, Memory & Concurrency, Kernel Space, User Space Interfaces, sau đó tra Subsystem Drivers khi cần Linux Kernel Boot Process, Platform Device, Interrupt và bottom half, Kernel Space, User Space Interfaces
    B. Cơ chế bên trong và real-time Hiểu kernel lập lịch, quản lý bộ nhớ, file system thế nào, và cấu hình hệ thống có yêu cầu độ trễ Kernel Basics, hai trang Interrupt và Đồng bộ hóa của nhóm Interrupt, Memory & Concurrency, Kernel Internals, Real-time & CPU Isolation Interrupt và bottom half, Đồng bộ hóa trong kernel, Process và thread, Real-time Linux (PREEMPT_RT)
    C. Tìm lỗi Chọn công cụ và tìm lỗi trong code kernel Tracing & Debug, chọn trang theo triệu chứng Tracing và debug Linux kernel, Đọc kernel oops và panic, printk và kernel log

    Lối vào B không cần nhóm Driver Model & Device Tree, nhưng các trang Kernel Internals và Real-time dùng khái niệm ngắt, softirq, spinlock và RCU, nên cần đọc hai trang Interrupt và Đồng bộ hóa trước. Người đọc đã có nền có thể vào thẳng nhóm cần dùng; các trang có link tới khái niệm nền khi dùng tới.

    Các nhóm trang¶

    Các nhóm dưới đây theo đúng thứ tự trong menu bên trái. Trang ghi "chưa viết" đã có chỗ trong menu nhưng mới có dàn ý.

    Kernel Basics¶

    Nhóm này trình bày kernel từ lúc được nạp tới lúc chạy init, cách cấu hình và build kernel, cách mở rộng kernel bằng module, và chu kỳ phát hành.

    • Linux Kernel Boot Process: giao diện giữa bootloader và kernel, quá trình kernel khởi động, initcall, mount root filesystem và chạy init, debug quá trình boot.
    • Kernel Command Line: nguồn và cú pháp của command line, các tham số thường dùng, cách đặt trên từng nền tảng và cách kernel xử lý tham số.
    • Kernel Build (Kconfig, Kbuild) (chưa viết): Kconfig, Kbuild, cross compile, các sản phẩm build (Image, vmlinux, System.map, .dtb, .ko), build module ngoài cây nguồn.
    • Kernel Module: định nghĩa, module_init và module_exit, ví dụ hello world, build, in log, nạp và gỡ module.
    • Kernel Data Structure: linked list của kernel và container_of().
    • Kernel Release Process: chu kỳ phát triển, các nhánh, bản stable và LTS, cách đánh số phiên bản, chọn kernel cho sản phẩm nhúng.

    Một driver không chỉ là một module: nó phải được kernel ghép với thiết bị mà nó điều khiển, việc của driver model.

    Driver Model & Device Tree¶

    Nhóm này trình bày mô hình bus, device, driver của kernel và cách thiết bị được khai báo trên hệ nhúng.

    • Linux Device Driver Overview: nhập môn về device model, kernel module và character device.
    • Device Tree: các loại file, cú pháp node và property, địa chỉ, ngắt, tài nguyên clock và GPIO, binding, overlay, quan hệ với driver.
    • Platform Device: platform bus, ghép thiết bị và driver, cấu trúc platform_driver, lấy tài nguyên trong probe(), deferred probe.
    • Driver Core (kobject, sysfs, devres) (chưa viết): kobject, sysfs, uevent, devres và các hàm devm_*, thứ tự probe, device link.

    Khi probe() đã lấy được thanh ghi và ngắt, driver cần các cơ chế lõi của kernel để xử lý ngắt, bảo vệ dữ liệu dùng chung và cấp phát bộ nhớ.

    Interrupt, Memory & Concurrency¶

    Nhóm này trình bày các cơ chế lõi mà driver dựa vào, từ góc nhìn người viết driver. Hai trang đầu cũng là nền của lối vào B.

    • Interrupt và bottom half: đường đi của một ngắt, irqchip và IRQ domain, đăng ký handler, quy tắc trong ngữ cảnh ngắt, top half và bottom half (threaded IRQ, softirq, tasklet, workqueue).
    • Đồng bộ hóa trong kernel: nguồn gây đồng thời, atomic, spinlock, mutex, semaphore và wait queue, seqlock, RCU, memory barrier, chọn cơ chế.
    • Quản lý bộ nhớ trong driver: địa chỉ ảo và vật lý, zone, page allocator, kmalloc, vmalloc và kmem_cache, cờ GFP, cấp phát gắn với vòng đời thiết bị, truy cập vùng I/O.
    • DMA: DMA mask, hai kiểu ánh xạ DMA, scatter-gather, IOMMU, CMA, dmaengine.
    • Timer và delay (chưa viết): timer, hrtimer và các hàm delay mà driver dùng trực tiếp.

    Với các cơ chế này, driver đã điều khiển được phần cứng; bước tiếp theo là cung cấp dữ liệu và lệnh điều khiển cho ứng dụng.

    Kernel Space, User Space Interfaces¶

    Nhóm này trình bày ranh giới giữa kernel và user space và các interface để ứng dụng giao tiếp với kernel và driver.

    • Kernel Space, User Space Interfaces: privilege level, chia không gian địa chỉ, các hàm uaccess, bảng so sánh và cách chọn interface.
    • System Call: cơ chế gọi trên x86_64 và arm64, đường đi trong kernel, vDSO, thêm system call mới, công cụ theo dõi.
    • Character Device Driver: device file, số major và minor, khai báo character device, mutex, mmap, ioctl.
    • Device File và ioctl: file_operations, thiết kế lệnh ioctl, misc device, header UAPI, ví dụ đầy đủ.
    • Pseudo Filesystem (chưa viết): procfs, sysfs, debugfs, configfs.
    • mmap, UIO, dma-buf (chưa viết): chia sẻ bộ nhớ giữa kernel và user space.
    • Thông báo bất đồng bộ (chưa viết): các cách kernel chủ động báo event cho user space.
    • Netlink (chưa viết): giao tiếp hai chiều qua socket.
    • Interface nâng cao (chưa viết): các interface mới hoặc chuyên biệt.
    • ABI, bảo mật và độ ổn định (chưa viết): nguyên tắc thiết kế interface cho user space.
    • Lab tổng hợp (chưa viết): một driver mẫu xuất dữ liệu qua nhiều interface để so sánh.

    Tới đây driver đã đủ các phần chung; phần còn lại phụ thuộc subsystem mà thiết bị thuộc về.

    Subsystem Drivers¶

    Nhóm này là danh mục tra cứu, không có thứ tự đọc giữa các trang. Mỗi trang trình bày một subsystem hoặc framework: driver của thiết bị cụ thể đăng ký vào đó thay vì tự làm lại phần chung. Các trang được chia thành bốn nhóm con Bus, Hardware Frameworks, I/O & Media và Storage; danh sách trang nằm trong mục "Danh mục subsystem" bên dưới, cùng các subsystem chưa có trang.

    Nhóm tiếp theo bắt đầu lối vào B: thay vì nhìn kernel qua các API mà driver dùng, các trang đi vào cơ chế bên trong.

    Kernel Internals¶

    Nhóm này trình bày cơ chế bên trong kernel ở mức hệ thống, độc lập với việc viết driver.

    • Process và thread: task_struct, trạng thái task, current và kernel stack, clone, exec, kết thúc task, kernel thread, signal.
    • Scheduler: scheduling class, runqueue theo CPU, thời điểm lập lịch lại, preemption, lập lịch task thường, real-time class, deadline class, cân bằng tải, sched_ext.
    • SMP và CPU hotplug: mô hình SMP, khởi động core phụ, biến per-CPU, IPI, CPU hotplug, CPU topology, hệ nhiều core không đồng nhất.
    • Virtual Memory: VMA, page table trên Arm64, page fault và copy-on-write, reclaim, swap, OOM killer, CMA, huge page.
    • VFS và page cache: các đối tượng VFS, tra cứu đường dẫn, đường đi của open, read, write, page cache và writeback.
    • Security Subsystem (chưa viết): LSM, capabilities, seccomp xét như subsystem của kernel.

    Scheduler và cơ chế ngắt là nền để giới hạn độ trễ, chủ đề của nhóm cuối trong lối vào B.

    Real-time & CPU Isolation¶

    Nhóm này trình bày cách giới hạn độ trễ của kernel và dành riêng core cho workload real-time.

    • Real-time Linux (PREEMPT_RT): các mô hình preemption, ba cơ chế chính của PREEMPT_RT, viết mã cho kernel real-time, chính sách lập lịch real-time, cấu hình và đo độ trễ.
    • isolcpus: housekeeping, tham số isolcpus=, thay thế bằng cpuset của cgroup v2.
    • nohz_full: các chế độ quản lý tick, điều kiện dừng tick, RCU offload, chi phí đánh đổi.
    • IRQ affinity và irqbalance: giao diện /proc/irq, managed interrupt, irqbalance, cấu hình cho core cô lập.

    Mọi nhóm trên đều cần công cụ để quan sát và tìm lỗi; nhóm cuối gom các công cụ đó.

    Tracing & Debug¶

    Nhóm này là bộ công cụ dùng xuyên suốt, đọc theo tình huống: trang tổng quan của nhóm giúp chọn công cụ theo triệu chứng, rồi dẫn tới trang chi tiết. Khi bắt đầu viết driver, nên đọc sớm trang printk.

    • Tracing và debug Linux kernel: phân nhóm công cụ, so sánh mức can thiệp, chọn công cụ theo triệu chứng, cấu hình kernel cần có sẵn.
    • Log và tracing:
      • printk và kernel log: mức log, họ macro pr_*() và dev_*(), đọc log qua dmesg và /dev/kmsg.
      • Dynamic Debug: bật và tắt log debug lúc chạy, kể cả lúc boot và lúc nạp module.
      • FTrace: nguyên lý, kiến trúc và frontend của ftrace.
      • Tracepoint và trace events: hook tĩnh, bật và lọc event, định nghĩa trace event, trace-cmd.
      • eBPF và bpftrace (chưa viết).
      • perf trong kernel (chưa viết).
      • Đo độ trễ bằng tracing (chưa viết).
    • Chẩn đoán lỗi:
      • Đọc kernel oops và panic: các mức báo lỗi, cấu trúc bản tin oops, cờ taint, giải mã call trace, treo mà kernel tự phát hiện, giữ lại log.
      • Bộ phát hiện lỗi bộ nhớ và đồng bộ (chưa viết).
      • Debug bộ nhớ kernel (chưa viết).
      • Fault injection (chưa viết).
      • debugfs và truy cập thanh ghi (chưa viết).
    • Live debug:
      • KGDB và kdb: hai frontend kgdb và kdb, debug core, cấu hình, kết nối gdb qua cổng serial, GDB helper script.
      • KGDB trên QEMU: môi trường thực hành KGDB bằng máy ảo.
      • Debug kernel bằng JTAG: OpenOCD và gdb với khối debug phần cứng của SoC.
    • Post-mortem:
      • Kernel crash dump (kdump): nguyên lý capture kernel, cấu hình, tham số crashkernel, ghi và phân tích dump.

    Danh mục subsystem¶

    Subsystem là một framework chung do kernel cung cấp cho một nhóm thiết bị hoặc chức năng. Các bảng dưới chia subsystem theo nhóm con của Subsystem Drivers, thêm hai bảng cho device model và mạng; cột cuối để trống khi tab chưa có trang tương ứng. Danh sách không đầy đủ tuyệt đối; danh sách đầy đủ nằm trong Documentation/ của kernel source hoặc tại docs.kernel.org.
