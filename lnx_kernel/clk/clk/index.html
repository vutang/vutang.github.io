    Common Clock Framework (CCF) trong Linux kernel¶

    CCF (CONFIG_COMMON_CLK) tách consumer (<linux/clk.h>) khỏi provider (<linux/clk-provider.h>) và giữ cây clock, refcount, rate cache và locking ở core drivers/clk/clk.c. Bản nháp v0.1, tham chiếu kernel docs v7.3.

    1. Introduction¶

    CCF được Mike Turquette (Linaro/TI) đưa vào mainline ở v3.4 (2012), thay cho các struct clk riêng của từng kiến trúc ARM (OMAP, i.MX, Tegra…) vốn khiến không thể build kernel đa nền tảng.

    Ý tưởng cốt lõi: một struct clk chung, một implementation chung cho API clk.h; phần cứng chỉ cung cấp callback qua struct clk_ops và nhúng một struct clk_hw. Công việc dựa trên nền của Jeremy Kerr và Ben Herrenschmidt.

    CCF có quản lý CCF không quản lý
    Clock nội bộ SoC: PLL, divider, gate, mux cho peripheral, bus, CPU Nguồn thời gian hệ thống (clocksource/clockevent, kernel/time/)
    Clock generator ngoài qua I²C/SPI (Si5341, Si570, CDCE9xx…) PTP Hardware Clock (/dev/ptpN, drivers/ptp/)
    Phase, duty cycle, accuracy (ppb), spread spectrum DPLL cho SyncE/PTP (drivers/dpll/, netlink)

    Ranh giới này quan trọng với hệ thống gNodeB, xem mục 11.

    2. Kiến trúc tổng thể¶

    CCF có ba lớp, nối với nhau bởi struct clk_hw:

    1. Consumer API (include/linux/clk.h): driver thiết bị chỉ thấy struct clk * dạng opaque.
    2. Core (drivers/clk/clk.c): duy trì cây clk_core, refcount, cache rate, notifier, locking, debugfs.
    3. Provider (include/linux/clk-provider.h): driver phần cứng định nghĩa struct clk_foo { struct clk_hw hw; ... } và một const struct clk_ops.

    Giữa consumer và core có lớp lookup: Device Tree (clocks/clock-names), clkdev cho board không có DT, hoặc ACPI.

    3. Cấu trúc dữ liệu¶

    Struct Ai sở hữu Vai trò
    struct clk core, cấp cho từng consumer Handle per-consumer: mỗi lần clk_get() tạo một struct clk mới, chứa min_rate/max_rate riêng. Nhiều struct clk → 1 clk_core.
    struct clk_core core (private trong clk.c) Node trong cây: parent, children, parents[], rate, req_rate, enable_count, prepare_count, protect_count, flags, orphan, accuracy, phase, duty, notifier.
    struct clk_hw provider (nhúng trong struct phần cứng) Cầu nối: provider dùng container_of() để lấy lại struct riêng; chứa hw->init (chỉ dùng lúc đăng ký).

    Provider mô tả clock lúc đăng ký bằng struct clk_init_data. Nên dùng parent_data (.fw_name khớp clock-names của chính provider node, hoặc .index) hoặc parent_hws thay vì parent_names, vì tra cứu theo chuỗi toàn cục dễ vỡ và phụ thuộc thứ tự probe.

    struct clk_init_data {
    const char      *name;
    const struct clk_ops    *ops;
    /* Chỉ dùng MỘT trong ba cách mô tả parent: */
    const char      * const *parent_names;  /* legacy */
    const struct clk_parent_data    *parent_data;   /* khuyến nghị */
    const struct clk_hw **parent_hws;       /* parent cùng driver */
    u8          num_parents;
    unsigned long       flags;
};

    struct clk_ops¶

    .enable/.disable/.is_enabled chạy dưới enable_lock (spinlock) và không được ngủ. Mọi callback còn lại chạy dưới prepare_lock (mutex) và được ngủ. .round_rate không còn tồn tại, xem mục 9.1.

    struct clk_ops {
    /* sleepable, dưới prepare_lock */
    int  (*prepare)(struct clk_hw *hw);
    void (*unprepare)(struct clk_hw *hw);
    int  (*is_prepared)(struct clk_hw *hw);
    void (*unprepare_unused)(struct clk_hw *hw);

    /* atomic, dưới enable_lock, KHÔNG được ngủ */
    int  (*enable)(struct clk_hw *hw);
    void (*disable)(struct clk_hw *hw);
    int  (*is_enabled)(struct clk_hw *hw);
    void (*disable_unused)(struct clk_hw *hw);

    /* rate / parent, sleepable */
    unsigned long (*recalc_rate)(struct clk_hw *hw, unsigned long parent_rate);
    int  (*determine_rate)(struct clk_hw *hw, struct clk_rate_request *req);
    int  (*set_rate)(struct clk_hw *hw, unsigned long rate, unsigned long parent_rate);
    int  (*set_parent)(struct clk_hw *hw, u8 index);
    u8   (*get_parent)(struct clk_hw *hw);
    int  (*set_rate_and_parent)(struct clk_hw *hw, unsigned long rate,
                    unsigned long parent_rate, u8 index);

    /* thuộc tính tín hiệu */
    unsigned long (*recalc_accuracy)(struct clk_hw *hw, unsigned long parent_accuracy);
    int  (*get_phase)(struct clk_hw *hw);
    int  (*set_phase)(struct clk_hw *hw, int degrees);
    int  (*get_duty_cycle)(struct clk_hw *hw, struct clk_duty *duty);
    int  (*set_duty_cycle)(struct clk_hw *hw, struct clk_duty *duty);
    int  (*set_spread_spectrum)(struct clk_hw *hw,
                    const struct clk_spread_spectrum *ss_conf); /* mới */

    /* vòng đời / PM / debug */
    int  (*save_context)(struct clk_hw *hw);
    void (*restore_context)(struct clk_hw *hw);
    int  (*init)(struct clk_hw *hw);
    void (*terminate)(struct clk_hw *hw);
    void (*debug_init)(struct clk_hw *hw, struct dentry *dentry);
};

    Callback bắt buộc theo loại phần cứng (theo kernel docs):

    Callback gate đổi rate single parent mux root
    .enable / .disable / .is_enabled y
    .recalc_rate / .determine_rate / .set_rate y
    .set_parent / .get_parent n y n

    Core flags quan trọng¶

    Flag Ý nghĩa Khi nào dùng
    CLK_SET_RATE_PARENT Đẩy yêu cầu đổi rate lên parent Gate/divider con muốn PLL cha đổi theo
    CLK_SET_RATE_GATE / CLK_SET_PARENT_GATE Phải tắt clock khi đổi rate/parent PLL không glitch-free
    CLK_SET_RATE_UNGATE Clock phải đang chạy mới đổi rate được Một số PLL cần lock
    CLK_SET_RATE_NO_REPARENT Không tự đổi parent khi set_rate Mux có parent cố định chủ ý
    CLK_IS_CRITICAL Không bao giờ gate DDR, interconnect, CPU clock
    CLK_IGNORE_UNUSED Không tắt trong clk_disable_unused() Clock dùng ngoài tầm nhìn kernel (FPGA PL, co-processor)
    CLK_GET_RATE_NOCACHE Luôn đọc lại rate từ HW Clock bị firmware/HW khác thay đổi
    CLK_OPS_PARENT_ENABLE Parent phải bật khi gate/ungate/set_rate/reparent Thanh ghi clock nằm trong domain của parent
    CLK_RECALC_NEW_RATES Recalc sau notifier Notifier có thể sửa HW
    CLK_DUTY_CYCLE_PARENT Chuyển tiếp duty cycle lên parent Gate trong suốt với duty

    4. Consumer API¶

    CCF tách bật clock thành hai pha. clk_prepare() có thể ngủ (khóa PLL, gọi I²C tới clock generator ngoài, gọi firmware) và gọi khi thiết bị có thể sẽ cần clock. clk_enable() là atomic, gọi được từ IRQ handler và bắt buộc phải prepare trước. Refcount lên cây: enable một leaf sẽ enable toàn bộ ancestor.

    static int foo_probe(struct platform_device *pdev)
{
    struct device *dev = &pdev->dev;
    struct clk *apb, *ref;
    int ret;

    /* get + prepare + enable, tự dọn khi unbind (v6.3+) */
    apb = devm_clk_get_enabled(dev, "apb");
    if (IS_ERR(apb))
        return dev_err_probe(dev, PTR_ERR(apb), "no apb clock\n");

    /* clock tuỳ chọn: trả NULL (không lỗi) nếu DT không khai báo */
    ref = devm_clk_get_optional(dev, "ref");
    if (IS_ERR(ref))
        return PTR_ERR(ref);

    /* hỏi trước rate thực tế đạt được, rồi mới set */
    long r = clk_round_rate(ref, 122880000);    /* 122.88 MHz */
    ret = clk_set_rate(ref, r);
    if (ret)
        return ret;

    /* khoá rate để consumer khác không đổi dưới chân mình */
    ret = devm_clk_rate_exclusive_get(dev, ref);
    ...
}
    Nhóm API
    Lấy handle devm_clk_get[_optional][_enabled\|_prepared](), devm_clk_bulk_get_all_enabled(), of_clk_get_by_name()
    Bật/tắt clk_prepare_enable(), clk_disable_unprepare(), clk_bulk_*()
    Rate clk_get_rate(), clk_round_rate(), clk_set_rate(), clk_set_rate_range(), clk_set_min_rate()
    Bảo vệ rate clk_rate_exclusive_get()/put(), clk_set_rate_exclusive()
    Parent clk_set_parent(), clk_get_parent(), clk_has_parent()
    Tín hiệu clk_set_phase(), clk_set_duty_cycle(), clk_get_accuracy()
    Theo dõi clk_notifier_register(): nhận PRE/POST/ABORT_RATE_CHANGE

    clk_round_rate() phía consumer vẫn còn; chỉ callback .round_rate của provider bị xóa. Core giờ hiện thực nó bằng .determine_rate.

    5. Provider API¶

    Phần lớn cây clock của SoC được ghép từ các khối dựng sẵn trong drivers/clk/clk-*.c:

    Type Đặc điểm Helper đăng ký
    fixed-rate Luôn chạy, rate cố định clk_hw_register_fixed_rate()
    fixed-factor Nhân/chia rate parent bằng hằng số, không gate devm_clk_hw_register_fixed_factor()
    gate Cùng rate với parent, chỉ bật/tắt devm_clk_hw_register_gate()
    divider Chia rate parent, hệ số chọn từ bảng khi đăng ký devm_clk_hw_register_divider[_table]()
    mux Chọn một trong nhiều parent, không gate devm_clk_hw_register_mux()
    fractional divider Chia theo tỉ số m/n clk_hw_register_fractional_divider()
    composite Ghép mux + divider + gate clk_hw_register_composite()

    Ví dụ clock riêng: divider¶

    #include <linux/clk-provider.h>

struct foo_div {
    struct clk_hw   hw;
    void __iomem    *reg;
    spinlock_t  *lock;      /* chia sẻ thanh ghi với gate khác */
};
#define to_foo_div(_hw) container_of(_hw, struct foo_div, hw)

static unsigned long foo_div_recalc_rate(struct clk_hw *hw, unsigned long prate)
{
    u32 div = (readl(to_foo_div(hw)->reg) & 0xff) + 1;
    return DIV_ROUND_UP_ULL(prate, div);
}

static int foo_div_determine_rate(struct clk_hw *hw, struct clk_rate_request *req)
{
    unsigned int div = DIV_ROUND_CLOSEST(req->best_parent_rate, req->rate);

    div = clamp(div, 1U, 256U);
    req->rate = req->best_parent_rate / div;
    return 0;
}

static int foo_div_set_rate(struct clk_hw *hw, unsigned long rate, unsigned long prate)
{
    struct foo_div *d = to_foo_div(hw);
    unsigned long flags;
    u32 val;

    spin_lock_irqsave(d->lock, flags);
    val = readl(d->reg) & ~0xff;
    writel(val | (DIV_ROUND_CLOSEST(prate, rate) - 1), d->reg);
    spin_unlock_irqrestore(d->lock, flags);
    return 0;
}

static const struct clk_ops foo_div_ops = {
    .recalc_rate    = foo_div_recalc_rate,
    .determine_rate = foo_div_determine_rate,
    .set_rate   = foo_div_set_rate,
};

    Đăng ký và expose ra DT bằng clk_hw_onecell_data:

        struct clk_hw_onecell_data *data;

    data = devm_kzalloc(dev, struct_size(data, hws, NR_CLKS), GFP_KERNEL);
    data->num = NR_CLKS;

    init.name = "foo_div";
    init.ops = &foo_div_ops;
    init.parent_data = &(const struct clk_parent_data){ .fw_name = "ref" };
    init.num_parents = 1;
    div->hw.init = &init;

    ret = devm_clk_hw_register(dev, &div->hw);
    data->hws[FOO_CLK_DIV] = &div->hw;

    return devm_of_clk_add_hw_provider(dev, of_clk_hw_onecell_get, data);

    spinlock_t *lock riêng của driver là bắt buộc khi một thanh ghi chứa bit của cả nhóm atomic (enable) lẫn nhóm sleepable (set_rate): CCF không tự bảo vệ chéo giữa hai nhóm (mục 7).

    .determine_rate¶

    struct clk_rate_request gồm rate (mục tiêu), min_rate/max_rate (gộp ràng buộc từ mọi consumer), best_parent_rate, best_parent_hw. Provider sửa req->rate thành rate thực sự đạt được và, với mux hoặc CLK_SET_RATE_PARENT, đề xuất parent. Helper có sẵn: clk_hw_determine_rate_no_reparent(), __clk_mux_determine_rate[_closest](), divider_determine_rate(), clk_hw_forward_rate_request().

    6. Device Tree binding¶

    /* provider */
clkc: clock-controller@ff5e0000 {
    compatible = "vendor,foo-clkc";
    reg = <0xff5e0000 0x1000>;
    #clock-cells = <1>;         /* 1 cell = clock ID */
    clocks = <&osc_33m>, <&pl_ref>;
    clock-names = "ref", "pl_ref";      /* khớp parent_data.fw_name */
};

/* consumer */
uart0: serial@ff000000 {
    clocks = <&clkc 56>, <&clkc 31>;
    clock-names = "uart_clk", "pclk";

    /* core tự áp dụng lúc probe, qua of_clk_set_defaults() */
    assigned-clocks = <&clkc 56>;
    assigned-clock-rates = <100000000>;
    assigned-clock-parents = <&clkc 3>;
    /* đang được đề xuất: assigned-clock-sscs = <modfreq_hz spread_bp method>; */
};
    • #clock-cells = <0> cho provider một clock; <1> cho clock-controller (ID trong include/dt-bindings/clock/*.h); một số SoC dùng <2> (ví dụ QorIQ: type + index).
    • Nếu parent chưa đăng ký, clock con thành orphan và tự được nhận khi parent xuất hiện; clk_get() trên orphan thường nhận -EPROBE_DEFER.

    7. Locking, clk_set_rate và PREEMPT_RT¶

    CCF dùng hai lock toàn cục, cả hai reentrant cho cùng task:

    Lock Kiểu Bảo vệ Ngữ cảnh gọi
    prepare_lock mutex prepare/unprepare, mọi thao tác rate, parent, phase, duty, đăng ký clock Chỉ process context
    enable_lock spinlock_t enable/disable Được phép atomic
    • Driver không cần tự khóa tài nguyên chia sẻ trong cùng một nhóm, nhưng phải tự khóa tài nguyên chia sẻ giữa hai nhóm (ví dụ một thanh ghi chứa cả bit gate lẫn trường divider).
    • Core reentrant: .set_rate của clock A được phép gọi clk_set_rate() trên clock B.
    • prepare_lock là toàn cục, nên một clk_set_rate() chậm (PLL relock, I²C tới clock generator ngoài, round-trip firmware) chặn mọi thao tác prepare/rate của toàn hệ thống.

    Luồng clk_set_rate()¶

    1. Kiểm tra: clamp vào [min, max] gộp từ mọi struct clk của clock; nếu rate bị consumer khác khóa bằng clk_rate_exclusive_get() thì trả -EBUSY.
    2. clk_calc_new_rates() (bottom-up): gọi .determine_rate ở node đích; với CLK_SET_RATE_PARENT, đệ quy lên parent với best_parent_rate đề xuất. Mux có thể chọn parent mới.
    3. PRE_RATE_CHANGE: notifier được gọi cho cả subtree; nếu một notifier trả NOTIFY_BAD, core gửi ABORT_RATE_CHANGE và dừng.
    4. clk_change_rate() (top-down): gọi .set_parent/.set_rate (hoặc .set_rate_and_parent), tôn trọng CLK_SET_RATE_GATE, CLK_OPS_PARENT_ENABLE.
    5. Recalc + POST_RATE_CHANGE: .recalc_rate cập nhật cache cho subtree; nhả prepare_lock.

    Notifier thường dùng để cpufreq chuyển điện áp, DDR controller chuyển timing, UART tính lại baud divisor.

    Hệ quả trên PREEMPT_RT¶

    1. enable_lock trở thành sleeping lock (rt_mutex). clk_enable() từ IRQ handler threaded vẫn ổn, nhưng gọi từ ngữ cảnh thực sự atomic (hard-IRQ IRQF_NO_THREAD, đang giữ raw_spinlock_t, preempt_disable()) là lỗi, sẽ có cảnh báo "sleeping function called from invalid context" khi bật CONFIG_DEBUG_ATOMIC_SLEEP.
    2. prepare_lock toàn cục là nguồn priority inversion tiềm ẩn. Task RT ưu tiên cao (ví dụ thread điều khiển fronthaul) gọi clk_set_rate() trong khi một kworker priority thấp đang giữ lock để relock PLL hay chờ firmware sẽ bị chặn. Priority inheritance tránh được inversion không giới hạn, nhưng độ trễ vẫn bằng thời gian critical section kia. Nguyên tắc: không thao tác clock trong đường nóng RT; cấu hình rate một lần lúc init (hoặc qua assigned-clock-rates).
    3. clk_disable_unused() chạy ở late_initcall_sync và có thể tắt clock của khối FPGA PL hay IP mà kernel không biết đang dùng, gây treo hoặc mất dữ liệu ngay sau boot. Xử lý đúng: khai báo clock cho driver consumer, hoặc CLK_IGNORE_UNUSED/CLK_IS_CRITICAL trong provider. clk_ignore_unused trên boot args chỉ nên dùng khi debug.

    8. Debug và quan sát¶

    mount -t debugfs none /sys/kernel/debug 2>/dev/null

# Toàn bộ cây: enable/prepare/protect count, rate, accuracy, phase, duty, consumer
cat /sys/kernel/debug/clk/clk_summary

# Dạng JSON, tiện cho script
cat /sys/kernel/debug/clk/clk_dump

# Clock chưa có parent (thường do thiếu provider hoặc sai parent_data)
cat /sys/kernel/debug/clk/clk_orphan_summary

# Thuộc tính từng clock
ls /sys/kernel/debug/clk/<clk_name>/
#   clk_rate  clk_enable_count  clk_prepare_count  clk_flags
#   clk_parent  clk_possible_parents  clk_phase  clk_duty_cycle ...

    Ghi vào clk_rate, clk_parent… chỉ khả dụng khi build với #define CLOCK_ALLOW_WRITE_DEBUGFS trong clk.c (chủ ý không có Kconfig, chỉ dành cho bring-up).

    Tracepoint:

    # Theo dõi mọi thao tác clock lúc boot
... tp_printk trace_event=clk:*

# Hoặc runtime
echo 1 > /sys/kernel/tracing/events/clk/enable
cat /sys/kernel/tracing/trace_pipe
# events: clk_enable, clk_disable, clk_prepare, clk_set_rate[_complete],
#         clk_set_parent, clk_set_phase, clk_set_duty_cycle ...

    Để biết clk_disable_unused() đã tắt những gì: boot với tp_printk trace_event=clk:clk_disable. Core CCF còn có bộ test KUnit (drivers/clk/clk_test.c, clk-gate_test.c…):

    ./tools/testing/kunit/kunit.py run --kunitconfig=drivers/clk

    9. Phát triển gần đây (2025–2026)¶

    Xóa .round_rate khỏi clk_ops¶

    Trong 2025, Brian Masney (Red Hat) gửi loạt hơn 100 patch chuyển toàn bộ driver trong tree sang .determine_rate bằng Coccinelle; khi một driver định nghĩa cả hai, core vốn chỉ dùng .determine_rate. Commit cuối xóa hẳn callback này vào đầu 2026, và tài liệu kernel v7.3 không còn .round_rate trong struct clk_ops.

    Hệ quả với driver out-of-tree (BSP vendor, driver nội bộ): clock driver nào còn .round_rate sẽ không biên dịch được trên kernel mới. Chuyển đổi gần như cơ học:

    /* trước */
static long foo_round_rate(struct clk_hw *hw, unsigned long rate, unsigned long *prate)
{ return calc(rate, *prate); }

/* sau */
static int foo_determine_rate(struct clk_hw *hw, struct clk_rate_request *req)
{
    req->rate = calc(req->rate, req->best_parent_rate);
    return 0;
}

    Spread spectrum (SSC)¶

    Peng Fan (NXP) đề xuất API từ đầu 2025, v9 vào 3/2026. Callback mới .set_spread_spectrum nhận tần số điều chế (Hz), độ trải (basis point) và phương pháp; thuộc tính DT assigned-clock-sscs được core áp dụng lúc probe, nhằm giảm EMI. Người dùng đầu tiên là clk-scmi trên i.MX95 (firmware SCMI thực hiện SSC); TI cũng có patch tương tự cho clk-sci trên K3.

    Rust¶

    Viresh Kumar (Linaro) đưa abstraction Rust tối thiểu cho phía consumer vào rust/kernel/clk.rs (cùng loạt cpufreq/OPP): Clk, OptionalClk, prepare_enable(), rate(), set_rate(), kiểu Hertz. Chưa có abstraction phía provider.

    10. Ví dụ trên nền tảng của team¶

    Xilinx ZynqMP: clock qua firmware (drivers/clk/zynqmp/)¶

    Linux ở EL1 không ghi trực tiếp thanh ghi CRL_APB/CRF_APB. Mọi thao tác clock đi qua EEMI → ATF (EL3) → PMU firmware:

    clk_set_rate()  →  zynqmp_clk_divider_set_rate()
                →  zynqmp_pm_clock_setdivider()      /* drivers/firmware/xilinx/zynqmp.c */
                →  SMC → ATF → IPI → PMU FW  →  ghi thanh ghi CRL/CRF
    • Topology không hard-code trong kernel: clkc.c hỏi PMU firmware (PM_QUERY_DATA: tên, topology, parent, attribute) lúc probe rồi dựng cây bằng các type riêng zynqmp_clk_register_{pll,divider,mux,gate}.
    • Mỗi thao tác clock là một round-trip SMC + IPI và giữ prepare_lock suốt thời gian đó, thêm một lý do không đổi clock lúc runtime trên hệ RT.
    • Clock cho PL (fabric): pl0_ref…pl3_ref (FCLK0–3) do PS cấp. Nếu IP trong PL không có consumer khai báo trong DT, clk_disable_unused() có thể tắt chúng. Giải pháp chuẩn: khai báo clocks = <&zynqmp_clk 71> (PL0_REF) cho node IP, hoặc dùng assigned-clock-rates.
    • Kiểm tra: cat /sys/kernel/debug/clk/clk_summary | grep -E "pl[0-3]_ref|dpll|vpll|iopll|rpll|apll".

    NXP LX2160A: QorIQ clockgen (drivers/clk/clk-qoriq.c)¶

    • Một driver chung cho họ QorIQ/Layerscape; compatible fsl,lx2160a-clockgen.
    • #clock-cells = <2>: cell đầu là loại clock (sysclk, cmux, hwaccel, fman, platform PLL), cell sau là index (include/dt-bindings/clock/fsl,qoriq-clockgen.h).
    • Cluster PLL + CMUX cấp clock cho cụm Cortex-A72; qoriq-cpufreq dùng clk_set_parent() trên CMUX để chuyển giữa các đầu ra PLL/divider, ví dụ điển hình của mux-based DVFS.
    • Peripheral (DPAA2, I²C, eSDHC…) phần lớn lấy clock từ platform PLL qua hệ số chia cố định.

    Clock generator ngoài¶

    Si5341 (clk-si5341.c), Si570 (clk-si570.c), có trên board ZCU102, được mô hình hóa như provider CCF qua I²C/regmap. Vì I²C có thể ngủ, thao tác thực sự nằm ở .prepare/.set_rate, không ở .enable.

    11. Discussion¶

    CCF là "cây chia tần", không phải "hệ đồng bộ". CCF tối ưu cho mô hình nguồn cố định → PLL → các nhánh chia/gate, rate là số nguyên Hz và trạng thái bật/tắt. Nó không mô hình hóa khóa pha theo nguồn ngoài, holdover hay trạng thái lock của DPLL. Với chuỗi đồng bộ của gNodeB (GNSS 1PPS → DPLL/jitter cleaner → clock cho RF/JESD204/eCPRI), quản lý trạng thái đồng bộ thuộc subsystem DPLL (drivers/dpll/, netlink) và PTP (drivers/ptp/); CCF chỉ hợp lý cho phần chọn tần số đầu ra của clock generator.

    Độ chính xác của rate. Rate là unsigned long Hz, đủ lớn trên ARM64, nhưng các tần số kiểu 122.88 MHz hay 245.76 MHz qua nhiều tầng divider/fractional có thể bị làm tròn. Luôn đọc lại clk_get_rate() sau khi set và kiểm tra accuracy (ppb) nếu provider có cung cấp.

    Lock toàn cục là điểm yếu đã biết. Thay prepare_lock bằng lock chi tiết hơn (theo clock hay subtree) đã được đề xuất nhiều lần, nhưng độ phức tạp (reparent đổi ranh giới subtree, tính reentrant) khiến mainline vẫn giữ thiết kế hai lock toàn cục.

    Hướng đi tiếp theo:

    • Đọc kỹ drivers/clk/clk.c: clk_core_set_rate_nolock(), clk_calc_new_rates(), clk_propagate_rate_change(), __clk_init_parent() và cơ chế orphan reparent.
    • So sánh mô hình CCF với SCMI clock protocol (firmware-managed clock, giống hướng ZynqMP EEMI).
    • Khảo sát drivers/dpll/ và quan hệ với CCF cho chip timing dùng trong gNodeB.
    • Kiểm thử trên ZCU102: dump clk_summary, đo thời gian một clk_set_rate() qua EEMI bằng ftrace.
