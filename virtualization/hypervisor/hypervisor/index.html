    Hypervisor & Hyper-V¶

    Tổng hợp từ cuộc trao đổi ngày 13/10/2026: kiến trúc Hyper-V, Linux làm root partition (mshv) và trình tự boot.

    Bối cảnh: Microsoft đóng góp driver pvIOMMU cho Linux guest trên Hyper-V, xem bài pvIOMMU: Hyper-V đưa DMA protection vào Linux guest.

    Hyper-V là gì, dùng ở đâu¶

    Hyper-V là hypervisor loại 1 (bare-metal) của Microsoft, chạy trực tiếp trên phần cứng và dùng ảo hóa phần cứng (Intel VT-x, AMD-V) để cô lập các VM.

    • Microsoft Azure: nền tảng ảo hóa bên dưới của hầu hết VM trên Azure.
    • Windows Server, Windows 10/11 Pro: VM tại chỗ, dev/test.
    • WSL2: thực chất là VM Linux nhẹ chạy trên Hyper-V.
    • Windows Sandbox, Docker Desktop và các lớp ảo hóa tương tự.
    • Bảo mật Windows: VBS, Credential Guard dùng hypervisor để cô lập.
    • Hạ tầng doanh nghiệp: private cloud, VDI, Azure Stack HCI.

    Các loại hypervisor¶

    Loại Đặc điểm Ví dụ
    Type 1 (bare-metal) Chạy trực tiếp trên phần cứng, hiệu năng và cô lập tốt, dùng cho server và cloud ESXi, Hyper-V, Xen, KVM, Proxmox
    Type 2 (hosted) Chạy như ứng dụng trên OS có sẵn, thêm một lớp overhead, tiện cho desktop và học tập VirtualBox, VMware Workstation/Fusion, Parallels
    • Ranh giới mờ: KVM là module trong kernel Linux nên vừa giống Type 1 vừa giống Type 2 (thường xếp Type 1). Hyper-V cài trên Windows vẫn là Type 1, vì khi bật thì Windows host trở thành một VM (root partition) chạy trên hypervisor.
    • Phân loại theo kỹ thuật: full virtualization, para-virtualization (hypercall, virtio, VMBus), hardware-assisted (mặc định hiện nay).
    • Container (Docker, LXC) dùng chung kernel host nên không phải hypervisor. Kata Containers và Firecracker chạy mỗi container trong một micro-VM.

    Kiến trúc Hyper-V¶

    Hyper-V theo kiểu microkernelized hypervisor: hypervisor giữ rất ít chức năng, phần còn lại đẩy lên root partition.

    • Hypervisor: lớp mỏng ở mức đặc quyền cao nhất. Quản lý partition, lập lịch CPU, quản lý bộ nhớ qua SLAT (EPT/NPT), hypercall và ngắt (SynIC), VTL cho tính năng bảo mật như VBS.
    • Root partition: OS host (Windows hoặc Linux), giữ driver phần cứng thật và các service quản lý VM (VMMS, VM Worker Process). Các VSP xử lý I/O storage và network cho guest.
    • Child partition: các VM guest, dùng VSC (hv_netvsc, hv_storvsc) và các enlightenment thay vì driver phần cứng thật.
    • VMBus: kênh giao tiếp VSC ↔ VSP dựa trên ring buffer trong bộ nhớ chia sẻ.
    • Hệ quả: hypervisor nhỏ nên bề mặt tấn công nhỏ; đổi lại I/O của guest phụ thuộc root partition, nên có các hướng như passthrough thiết bị (DDA/VFIO) và pvIOMMU.

    Hyper-V và Linux¶

    Hypervisor là phần mềm của Microsoft (không open source), nhưng Linux tương tác với nó theo 3 cách:

    • Linux làm guest (phổ biến nhất): driver Hyper-V (hv_vmbus, hv_netvsc, hv_storvsc, hv_utils...) nằm sẵn trong kernel mainline do Microsoft đóng góp. Hầu hết distro chạy được ngay.
    • Linux làm root partition: qua driver MSHV (xem phần dưới). Hypervisor vẫn là binary của Microsoft, được nạp lúc boot trước kernel Linux. Hướng này được Microsoft dùng cho hạ tầng Azure, cùng các VMM nhẹ như Cloud Hypervisor có backend MSHV.
    • Dùng hypervisor khác trên Linux: KVM + QEMU (hoặc libvirt, Proxmox) là giải pháp native, Xen cũng là lựa chọn. KVM cũng chạy được bên trong VM Hyper-V nếu bật nested virtualization.

    mshv: Linux làm root partition¶

    • mshv_root là kernel driver/module trong drivers/hv/, tạo thiết bị /dev/mshv. Giao diện ioctl tương tự /dev/kvm, cho userspace VMM (như Cloud Hypervisor) tạo và chạy VM khi Linux là root partition trên Microsoft Hypervisor, không cần Windows.
    • Series patch v6 gửi ngày 14/3/2025, sau nhiều vòng review từ 2021. Các file chính: mshv_root_main.c, mshv_root_hv_call.c, mshv_synic.c, mshv_irq.c, mshv_eventfd.c; header UAPI là include/uapi/linux/mshv.h.
    • Bản v6 gọn lại interface bằng ioctl passthrough chung MSHV_ROOT_HVCALL để VMM gọi thẳng hypercall của hypervisor qua kernel.

    Hypervisor nạp vào đâu và tách biệt OS thế nào¶

    • Không có vùng chip riêng: hypervisor được nạp vào RAM thường, nhưng chạy ở mức đặc quyền CPU riêng. Bootloader (trên Windows là winload/hvloader) nạp binary vào RAM và bật chế độ ảo hóa trước khi nạp kernel OS. Với Linux root, quy trình tương tự nhưng chi tiết loader cần kiểm tra lại.
    • Mức đặc quyền: trên x86 là chế độ root của VT-x hoặc host mode của AMD-V ("ring -1"), trên ARM64 là EL2. OS (kể cả root partition) bị đưa xuống chế độ guest (non-root).
    • Bộ nhớ: SLAT (EPT/NPT) quyết định mỗi partition thấy RAM vật lý nào. Vùng của hypervisor không được map vào bảng này nên kernel Linux/Windows không đọc/ghi được, kể cả ở ring 0.
    • Chuyển ngữ cảnh: OS chỉ gọi hypervisor qua hypercall hoặc VM exit (lệnh nhạy cảm, truy cập MMIO, ngắt).
    • Lưu ý: CPU vẫn là một chip, hypervisor và OS thay nhau chạy trên cùng các core. Hypervisor là thành phần tin cậy nhất; secure boot và measured boot (TPM) giúp đảm bảo nó không bị sửa. Hypervisor không phải SMM hay Intel ME/AMD PSP (đó là các firmware riêng).

    Trình tự boot khi Linux là root¶

    Bình thường: bootloader → Linux (Linux là chủ phần cứng). Với Hyper-V root: bootloader → hypervisor → Linux, và hypervisor vẫn nắm quyền cao nhất suốt thời gian chạy.

    1. UEFI khởi tạo phần cứng, tìm bootloader.
    2. Bootloader đọc binary hypervisor vào RAM.
    3. Hypervisor bật VMX/SVM (EL2), dựng môi trường và tạo root partition.
    4. Kernel Linux chạy bên trong root partition (là guest ở chế độ non-root), nạp mshv_root.
    5. VMM mở /dev/mshv để tạo các VM con.

    • Hypervisor không chạy liên tục như một tiến trình mà chỉ chiếm CPU khi có sự kiện (hypercall, VM exit, ngắt, lập lịch VM). Phần lớn thời gian Linux chạy trực tiếp trên CPU với tốc độ gần native, nhưng hypervisor vẫn quyết định Linux thấy RAM, core và thiết bị nào.
    • Linux root không biết hoàn toàn về phần cứng thật, và việc tạo VM phải qua hypercall (vai trò của mshv_root). Root partition đặc quyền hơn các VM con nhưng vẫn không vượt quyền hypervisor.
